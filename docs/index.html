Project Overview

What is NavRL Bench?

NavRL Bench is a robotics project focused on goal-directed navigation in dynamic environments for the ROSMASTER M3 mecanum-wheel robot. The project trains a reinforcement-learning local controller from scratch and compares it directly against classical Nav2 controllers.

The RL policy uses a ScanHistoryTransformerActor: a transformer network that processes 8-frame lidar history across 144 rays to learn ray-wise obstacle motion and closing rates, without ever receiving explicit obstacle state information. The critic has privileged access to the 4 nearest dynamic obstacles for better value estimation during training only.

Training runs in IsaacLab / Isaac Sim with real Nav2 path data from an AWS warehouse map. An adaptive curriculum progresses from simple goal-reaching through static obstacle avoidance to fast dynamic-obstacle scenarios, followed by domain randomization for sim-to-real transfer.

Problem Statement

Why train an RL local controller?

Classical Nav2 controllers are reliable and widely used for mobile robot navigation. However, when fast-moving obstacles repeatedly cross the robot path, they can become conservative, stop frequently, or struggle to maintain smooth progress toward the goal.

ROSMASTER M3 is a mecanum-wheel platform capable of lateral (strafe) motion. Classical controllers rarely exploit lateral velocity for obstacle avoidance. An RL controller trained with a 3D velocity action space — linear x, linear y, and angular z — can learn adaptive lateral bypass maneuvers that classical baselines do not produce.

This project investigates whether a trained scan-transformer policy can learn more adaptive dynamic-obstacle avoidance while still reliably reaching the assigned goal.

Core Engineering Contribution

RL training is more than a comparison item

ScanHistoryTransformerActor trained from scratch in IsaacLab

The policy uses a transformer over 144 lidar rays, where each token carries an 8-frame temporal history — enabling the actor to detect ray-wise closing motion and obstacle approach direction without seeing explicit obstacle states.

The training pipeline covers environment design, observation shaping, reward engineering, an adaptive obstacle curriculum, domain randomization for sim-to-real transfer, PPO training, and policy export into the Nav2 local control interface.

Controllers Compared

Classical baselines vs trained RL policy

DWB Controller

A classical Nav2 local controller based on the Dynamic Window Approach. Evaluates possible velocity commands using configurable critic functions and selects the best scoring motion.

MPPI Controller

A predictive sampling-based controller that evaluates thousands of candidate trajectories and selects the optimal control action by cost-weighted averaging.

Regulated Pure Pursuit

A path tracking controller that follows the global path while regulating speed based on path curvature and proximity to obstacles for collision avoidance.

PPO + ScanTransformer

A PPO policy with a ScanHistoryTransformerActor trained from scratch in IsaacLab. Outputs 3D mecanum velocity — including lateral strafe — integrated directly into Nav2's local controller interface.

The global planner and costmap remain unchanged across all controllers, keeping the benchmark focused on local navigation behavior: obstacle avoidance, slowing near hazards, choosing lateral detours, and recovery from blockages.

The RL policy receives a 16-value local path window from Nav2, the current heading and cross-track errors, 8-frame lidar history, and the robot's current velocity — all assembled by a lightweight Nav2 bridge node.

Benchmark Scenarios

Test Conditions

02

A moving obstacle briefly blocks the route, forcing the robot to slow down, wait, or locally avoid.

Goal Reaching with Moving Obstacles

A baseline scenario to verify normal local navigation behavior around fixed obstacles without dynamic elements.

Each controller is tested multiple times under the same scenario setup for statistically fair comparison.

Benchmark Principle

No unfair comparison

Classical controllers are used as available Nav2 baselines with their standard parameter tuning. The RL policy is trained from scratch by this project and evaluated under the exact same test setup.

The project does not assume that RL will always perform better. The goal is to measure where classical control performs well, where it struggles, and whether the trained scan-transformer policy provides better adaptability in fast-moving dynamic-obstacle scenarios — particularly exploiting mecanum lateral motion.
